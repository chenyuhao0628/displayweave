# DisplayWeave v0.3.5

发布日期：2026-11-10。正式版，Mac 构建号 / Android version code **24**。最终原生源码为 `13ecc58`。上一正式版为 [v0.3.4（23）](v0.3.4.zh-CN.md)。

## 改动

- **Android 接收端加固与解码恢复：** 在渲染停滞与编解码失败恢复期间，为旧版 V1 会话（`!negotiatedV2`）在 `decoderWorker` 上就地重建 `H264SurfaceDecoder`，并将空解码器丢帧归类为 `decoderUninitialized`。将 `OpenDisplayServer.stop()` 与 `decoderWorker` 关闭同步，并在独立线程异步释放 `MediaCodec`，防止停止会话阻塞或与正在执行的 `decodeAnnexB` 竞争。对关闭后的 `decoderWorker.execute(...)` 捕获 `RejectedExecutionException`。在 `ControlMessageWriter` 强制执行 `64 KiB` 单条负载上限及 `enqueueKeyFrameRequest` 的有界队列准入（`128` 条）。为 `OpenDisplayServer.Listener`、`NsdAdvertiser.Listener` 与 `WifiTcpReceiverTransport` 回调统一加入来源实例校验，防止已退役实例修改当前 UI 或前台保活状态。保持 `SecureTls` 纯 JDK 兼容，支持纯 `javac` TLS 互通与自测编译。
- **iOS/iPadOS 接收端与 Metal 渲染：** 消除 `MTKView.drawableSize` 主线程数据竞争，并在 `MetalVideoRenderer` 的重置与代次切换（`reset()` / `advanceGeneration()`）中保护纹理提交，防止旧 `CVDisplayLink` 回调或在途命令缓冲覆盖新状态。回到前台时重启带代次隔离的 ping 与首帧/视频超时监控。在系统渲染层与 Metal 路径切换时重置解码器。允许在有效能力范围内接受横竖屏互换的 `streamConfig`，并在隔离 iOS 运行时夹具中覆盖旋转准入验证。
- **Mac 发送端、接收端、USB 与共享策略：** Mac 接收端窗口展示与 `MacConnectionIcon` 状态改为以实际解码出 `videoSize` 为准，接管连接前先重置视频流状态，并防止重复发送 TLS hello。校验光标序号单调性与有限坐标边界。连接替换时清空在途发送计数，收紧重试与默认设置边界，并更新 `TestPatternWindow`。并发排空 `adb` 标准输出/错误管道且限制输出大小，为 `usbmuxd` 握手强制增加超时。修复 `ReceiverFrameDecoder` 流中途关键帧同步竞态并限制持久化写入边界。
- **CI、发行完整性与文档同步：** 强化 `check-release-integrity.py` 与 `check-release-links.sh` 以交叉核验所有活动下载表与 `public/` 更新源哈希，同步双语指南、系统架构说明与隐私披露页面，并清理未使用的网站静态资源与冗余 CSS 媒体查询。

既有线格式、Bonjour 服务名、bundle/package ID 与签名身份均保持不变。详见 [Apple 视频能力](../guides/apple-video.zh-CN.md)、[Android 接收会话控制](../reference/android-receiver-session-controls.zh-CN.md) 与 [Android 解码吞吐与恢复](../reference/android-decoder-throughput-recovery.zh-CN.md)。

## 上游审核

已获取 OpenSidecar 上游 `origin/main`（`0f44853`，自 v0.3.4 以来未变化）。它与共同祖先相差 417 个路径，继续延期至单独的兼容性审核。

## 兼容与验证

Mac ZIP 与引导式 DMG 使用固定 Apple Development 身份，并延续 v0.3.4（构建 23）应用的 designated requirement。产物包含 arm64/x86_64、启用加固运行时并验证了嵌套签名；**应用未公证**。Sparkle EdDSA 密钥与 Android 签名证书保持不变。iOS/iPadOS arm64 IPA 是无签名自签输入，不能直接安装。

本地验证通过：65 组 Swift 套件与生产方法夹具、Mac universal Debug 与 iOS 模拟器构建、Android 8 组自测/Debug/Lint、网站/双语文档（123 对）/发布完整性检查、Apple 分发与签名/目录/文档/打包维护检查和 36 项品牌导出。Apple↔Java 双向 TLS（`tools/test-tls-interop.py`）、Mac/iOS Keychain（`tools/test-apple-keychain.py --ios-simulator`）与隔离 iOS 视频准入运行时（`tools/test-ios-video-admission.py`）均通过。独立 CryptoKit 验证以应用内固定公钥核验 ZIP Ed25519 签名、长度和篡改拒绝。

本次实机验证：因仅内置显示器在线、没有独立显示器，虚拟显示测试记为 **SKIP**。本次发行会话未进行 23 → 24 隐私权限交互升级、实体 Android/iPad/双 Mac 串流、Intel 运行或耐久测试。既有的 iPad 容量回放与 Android 观察保留原验证范围。

Android 高帧率与 iPad 原生分辨率高刷均属实验功能。请求或协商的帧率不代表实体屏幕的实际刷新率。双设备串流、持续高刷表现、Intel 运行和长时间可靠性仍需独立实机验收。

发行与托管验证回执见[发行 PR #31](https://github.com/chenyuhao0628/displayweave/pull/31)（含针对 `workflow_contract` 中 `-source.tar.gz` 在 Ubuntu GNU `grep` 下的 `grep -Fq --` 兼容修复）。
