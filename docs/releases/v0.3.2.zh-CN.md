# DisplayWeave v0.3.2

发行日期：2026-10-26。**正式版**，Mac 构建号／Android version code 为 **21**。已审核原生源码为 `b01e1326263a537f1f7fee9ea13282fdfb39e77e`，源码 PR #22 合并为 `1bfa1ca`。上一正式版为 v0.3.1（20）。直接发布正式版，不设置公开 preview、beta 或 RC 阶段。

## 改动

- 新增 iMac 4K（4096×2304）、4.5K（4480×2520）和 5K（5120×2880）桌面档位。Retina 2× 下，5K 提供 2560×1440 逻辑点；已有保存档位含义保持不变。
- “原生”改为“跟随接收屏幕”，展示实际逻辑尺寸。桌面逻辑点／底层像素与编码视频尺寸分别显示，两台 Mac 均补充全屏提示。
- 将可能阻塞的 VideoToolbox 提交从采集／控制队列移到独立串行编码队列，最多保留两次提交。编码器创建、修改和销毁遵循同一顺序；过期代次不能更新替换后的会话。40/50 FPS 中间档位也使用两帧编码流水线。
- 默认开启“自动适配 Mac 编码负载”。连续三个活动画面过载窗口才调整，静止／稀疏动画和网络积压不会触发降级。分辨率优先保留细节、降低 FPS；帧率优先先降低视频尺寸，两者都不改变桌面／窗口布局。恢复需要五个健康活动窗口及至少 30 秒，恢复失败后延长等待。可单独关闭此功能，测试码率模式不启用。
- 采集调参限制为五秒，清理旧尺寸缓存，并处理停止、替换、编码回退、错误与迟到完成。失败时结束受影响会话，提示重连或关闭自动适配。
- 补充协商桌面／编码信息、平均编码提交耗时与压力诊断。Android 和 iOS 保留 v0.3.1 行为，提供匹配版本号的安装包。

[iMac 报告](../verification/imac-resolution-performance.zh-CN.md)分别记录日志证据、回归与实机验收。用户日志支持活动画面期间存在编码压力，但不能证明每次卡顿原因都相同。

## iMac 推荐设置

两台 Mac 都更新。选择“跟随接收屏幕”，接收端全屏，两台电脑使用相同 macOS 显示缩放。希望拖动／滚动更流畅时选择“帧率优先”，保持“自动适配 Mac 编码负载”开启；偏重文字细节时选择“分辨率优先”。降低视频画质可减轻负载，不需要重新排列桌面。

接收窗口会把整个桌面缩放到窗口内。3840×2160 Retina 桌面只有 1920×1080 逻辑点，铺满 5K 屏幕会放大窗口。新增 5K 桌面档位**不代表 5K 视频**：Apple 解码范围仍为横屏 4096×2304／竖屏 2304×4096。不承诺 4K/5K60 或双 Intel iMac 性能。

## 兼容与签名

GPL-3.0、上游署名、项目／bundle／包身份、已有偏好值、Bonjour、协议帧、安全配对、Sparkle 公钥和 Android 证书保持兼容。新增适配偏好默认开启，已有桌面选择保持不变。Mac 与实际下载的 v0.3.1 ZIP（构建 20）比较，验证代码身份要求、团队、bundle ID 和 universal 架构连续；未交互重测 20 → 21 隐私权限延续。

**Mac 仍采用 Apple Development 签名，未公证。** 若 macOS 阻止打开，按[安装与权限指南](../guides/mac-permissions.zh-CN.md)恢复。Android 沿用原项目证书；iOS 为无签名 arm64 重签输入，需要用户自己的有效 Apple 身份。安装包仅使用 GitHub Releases，更新元数据使用项目 GitHub Pages。

- 本地 Thread Sanitizer、真实 Apple↔Java TLS、Mac/iOS Keychain 与安全 Android 运行检查通过。安全 iOS 独立重跑通过；首次后台监听关闭检查失败，日志已保留，iOS 源码未修改。
- 独立内置显示器在线时，实际 AppKit 窗口／全屏／生命周期和三轮 1×/2× 虚拟显示器创建／清理通过。arm64/macOS 26.5.2 上三轮独立合成 4K 探针均编码 180/180 帧，约 60 FPS；新队列回调延迟中位数约 13.99 ms、p95 约 14.71 ms。此前受竞争影响的一轮跳过 84/180 帧，明确保留为不可直接比较的证据。
- 构建 21 的 Mac universal Release ZIP／DMG、加固运行时／嵌套签名及基线连续性、Android Release 证书、无签名 arm64 iOS 身份／归档卫生、bundle／feed 版本与六项文件哈希均通过。使用不变的内置 Sparkle 公钥独立完成 CryptoKit Ed25519 验证。打包重新运行七组 Android Java 测试。

本地证据：`artifacts/verification/imac-resolution-2026-10-26/` 与 `artifacts/verification/v0.3.2/`。最终发行／CI 回执见[检查清单](release-checklist.zh-CN.md)。

## 仍需实机验证

用户描述两台机器应该均为 2019 Intel iMac，具体 CPU/GPU/系统及接收端全屏状态未确认。真实双 iMac 延迟、缩放、适配／恢复、以太网双向、睡眠唤醒、能耗和耐久仍待验收。arm64 合成测试和 Intel 编译不能证明 Intel 驱动性能，见[复测步骤](../verification/imac-resolution-performance.zh-CN.md)。
