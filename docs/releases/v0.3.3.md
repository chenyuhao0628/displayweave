# DisplayWeave v0.3.3

Release date: 2026-10-27. Stable release, Mac build / Android version code **22**. The native implementation was reviewed at `bc928c3c26128ab690b0193801c8d363869fdd87`; the previous stable release was v0.3.2 (21).

## Changes

- Add automatic matching for Mac extended desktops using an eligible adjacent or main sender display, the receiver's aspect ratio and plausible system-reported physical sizes. Missing or implausible sizes fall back to a proportional estimate. Fullscreen on the intended receiving display is the starting point; windowed presentation and inaccurate display reports can change the result.
- New installations default to automatic matching. Existing installations retain their saved selections and previous default; choose **Automatic matching** once in the device's **Desktop size** control. Old peers without a usable installation identity keep receiver-matched geometry. iOS and Android retain receiver-derived geometry.
- Re-evaluate sender screen changes with debounce and cooldown. Rebuild only the affected session when its geometry changes; preserve the current desktop while a reference display is unavailable. The connection row separates the applied desktop from negotiated video dimensions and warns when the video raster is smaller than the backing pixels.
- Add optional Mac receiver physical-size fields while accepting older announcements. Update both Macs for the best available estimate; unknown or invalid fields fall back without rejecting the connection. Existing framing, identities and preferences are preserved.
- Update the separate customer evidence collector to recognize stored automatic desktop selections and defaults without exporting raw peer IDs.

See [desktop resolution](../guides/desktop-resolution.md) and the [verification record](../verification/automatic-desktop-matching.md).

## Important limits

Automatic matching is an estimate, not a physical calibration. The Apple video envelope remains **4096×2304**; this release does not provide native 5K video and a 5120×2880 desktop may still look soft. It does not establish the cause of every observed blur. Customer two-Mac results, including the 2560-point / 5K case, have not been physically verified.

## Compatibility and verification

The Mac ZIP and guided DMG were signed with the same Apple Development identity as the exact downloaded v0.3.2 app, verified as universal arm64/x86_64 with hardened runtime and nested signatures. **They are not notarized.** The original Sparkle public key and Android signing certificate are unchanged. The iOS arm64 IPA is an unsigned re-signing input and cannot be installed directly. Privacy permission continuity from build 21 to 22 was not interactively retested.

Local checks passed: 65 Swift suites and the current-method fixtures, universal Mac Debug and iOS Simulator builds, Android tests/Debug/Lint, website, paired documentation, release-link and maintenance checks, Apple↔Java TLS, Mac/iOS Keychain and the isolated secure Android receiver. The first disposable iOS Keychain simulator launch timed out; an isolated rerun passed. The secure iOS receiver's first run passed TLS/video checks but its background-listener check remained in the inactive scene phase; an isolated rerun passed the full test.

GitHub CI run `40449952568` failed a monitor-test assertion that assumed the test would resume before the cooldown elapsed. The test now compares actual callback timestamps and allows a deliberately late check; production monitor code and packaged native sources are unchanged.

The first extended Android experience run failed to locate a main-screen control while a settings dialog was still visible; isolated reruns passed synthetic-video aspect ratio, status, metrics, input and background checks. This does not establish a production root cause.

On the available Apple M5 Mac with an independent display online, isolated AppKit and virtual-display checks included a synthetic 2048×1152-point / 2× case. Those tests do not prove two-device streaming, Intel runtime, native 5K sharpness, latency or endurance. The [verification record](../verification/automatic-desktop-matching.md) separates implementation, automated checks and physical acceptance.
