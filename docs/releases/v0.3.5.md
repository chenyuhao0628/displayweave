# DisplayWeave v0.3.5

Release date: 2026-11-10. Stable release, Mac build / Android version code **24**. Final native source: `13ecc58`. Previous stable release: [v0.3.4 (23)](v0.3.4.md).

## Changes

- **Android receiver hardening and decoder recovery:** Recreate legacy V1 `H264SurfaceDecoder` in place on `decoderWorker` during render-stall and codec-failure recovery (`!negotiatedV2`), and classify null-decoder drops (`decoderUninitialized`). Synchronize `OpenDisplayServer.stop()` with `decoderWorker` shutdown and release `MediaCodec` asynchronously on a detached thread so stopping a session cannot block or race with active `decodeAnnexB` calls. Guard `decoderWorker.execute(...)` against `RejectedExecutionException` after shutdown. Enforce `ControlMessageWriter` payload bounds (`64 KiB` ceiling) and bounded queue admission (`128` entries) on `enqueueKeyFrameRequest`. Guard all `OpenDisplayServer.Listener`, `NsdAdvertiser.Listener` and `WifiTcpReceiverTransport` callbacks by source instance so retired servers cannot mutate replacement UI or foreground keep-alive state. Keep `SecureTls` pure-JDK compatible for plain-`javac` TLS interop and self-tests.
- **iOS/iPadOS receiver and Metal rendering:** Eliminate `MTKView.drawableSize` main-thread data races and guard `MetalVideoRenderer` across reset and generation epochs so stale `CVDisplayLink` callbacks or in-flight command buffers cannot overwrite textures after `reset()` or `advanceGeneration()`. Restart generation-scoped ping and video watchdog timers on foreground resume. Reset the active decoder when switching between system layer and Metal rendering paths. Accept swapped-orientation stream configurations within the active capability envelope and cover rotated admission in the isolated iOS runtime fixture.
- **Mac sender, receiver, USB and shared policies:** Gate Mac receiver window presentation and `MacConnectionIcon` status on decoded `videoSize` rather than raw packet arrival, reset stream state before binding an adopted connection, and prevent duplicate TLS hello messages. Validate cursor sequence monotonicity and finite coordinate bounds. Clear pending send counters on connection replacement, bound retry/default settings, and modernize `TestPatternWindow`. Drain `adb` stdout/stderr pipes concurrently with bounded output and enforce `usbmuxd` handshake timeouts. Resolve mid-stream keyframe synchronization races in `ReceiverFrameDecoder` and bound persistence writes.
- **CI, release integrity and documentation:** Tighten `check-release-integrity.py` and `check-release-links.sh` to verify every active download table and `public/` feed hash, synchronize bilingual guides, architecture overview and privacy disclosures, and remove unused web assets and redundant CSS media queries.

Existing wire framing, Bonjour service names, bundle/package IDs and signing identities are preserved. See [Apple video capabilities](../guides/apple-video.md), [Android receiver session controls](../reference/android-receiver-session-controls.md) and [Android decoder throughput and recovery](../reference/android-decoder-throughput-recovery.md).

## Compatibility and verification

The Mac ZIP and guided DMG use the pinned Apple Development identity and retain the designated requirement of the v0.3.4 (build 23) app. They are universal arm64/x86_64 with hardened runtime and nested signatures; **they are not notarized**. The Sparkle EdDSA key and Android signing certificate remain unchanged. The iOS/iPadOS arm64 IPA is an unsigned re-signing input, not directly installable.

Local verification passed: 65 Swift suites and current-method fixtures; Mac universal Debug and iOS Simulator builds; Android 8 self-test groups, Debug and Lint; website, bilingual docs (123 pairs) and release-integrity checks; Apple distribution/signing, workspace/docs/packaging maintenance and 36 brand exports. Apple↔Java mutual TLS (`tools/test-tls-interop.py`), Mac/iOS Keychain (`tools/test-apple-keychain.py --ios-simulator`) and isolated iOS video-admission runtime (`tools/test-ios-video-admission.py`) passed. Independent CryptoKit verification checked the ZIP Ed25519 signature against the embedded pinned public key, its length and tamper rejection.

Physical verification for this release: virtual-display testing **SKIP** because only the built-in display was online, with no independent display. No 23 → 24 interactive privacy-permission upgrade, physical Android/iPad/Mac-to-Mac streaming, Intel runtime or endurance test was performed in this release session. Inherited iPad capacity replay and Android observations retain their original scope.

Android high-refresh and iPad native-resolution high-refresh remain experimental. A requested or negotiated frame rate is not evidence of physical display refresh. Two-device streaming, sustained high-refresh behavior, Intel runtime and long-duration reliability require separate hardware acceptance.

Publication and hosted verification receipts: [release PR #31](https://github.com/chenyuhao0628/displayweave/pull/31).
