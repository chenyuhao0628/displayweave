# DisplayWeave v0.3.4

Release date: 2026-11-09. Stable release, Mac build / Android version code **23**. Includes the reviewed changes in PRs #25, #27, #28 and #29. Final native source: `4401828` (including two release-validation lifecycle fixes). Previous stable release: v0.3.3 (22).

## Changes

- Android adds an explicit experimental high-frame-rate trial and background keep-alive behavior. The trial relaxes the advertised throughput gate for compatible modes; it does not prove rendered FPS or sustained hardware performance. Background service behavior preserves receiver sessions during supported lifecycle transitions.
- Eligible iPad receivers add the opt-in **Native-resolution high refresh (experimental)** setting, off by default and applied to the next connection. It expands the Apple video capability envelope only when selected. It is not a fixed-120Hz mode; system scheduling, thermal state and power policy can lower actual presentation rate.
- Harden frame bounds, lifecycle cleanup, decoder recovery and receiver input/UI policies, with regression coverage and review fixes. Connection callbacks from a replaced Android receiver server are ignored so they cannot change the replacement session's foreground keep-alive state. Ordered service stop commands prevent immediate disconnects from cancelling foreground startup before acknowledgement.
- Export rounded Mac app icon tiles for the Dock and app switcher.

The trials retain the existing wire framing and application identities. See [Apple video capabilities](../guides/apple-video.md) and [Android receiver session controls](../reference/android-receiver-session-controls.md).

## Compatibility and verification

The Mac ZIP and guided DMG use the pinned Apple Development identity and retain the designated requirement of the downloaded v0.3.3 app. They are universal arm64/x86_64 with hardened runtime and nested signatures; **they are not notarized**. The Sparkle EdDSA key and Android signing certificate remain unchanged. The iOS/iPadOS arm64 IPA is an unsigned re-signing input, not directly installable.

Local verification passed: 65 Swift suites and current-method fixtures; Mac universal Debug and iOS Simulator builds; Android tests/Debug/Lint; website, bilingual docs and release checks; Apple distribution/signing, workspace/docs/packaging maintenance and 36 brand exports. Apple↔Java TLS, Mac/iOS Keychain and isolated secure iOS/Android runtime checks passed. The extended Android experience fixture also passed synthetic-video aspect ratio, concise default status, immediate metric toggles, letterbox rejection, centered input and stationary holds. Independent CryptoKit verification checked the ZIP Ed25519 signature against the embedded pinned public key, its length and tamper rejection.

Initial isolated Android runtime runs crashed with `ForegroundServiceDidNotStartInTimeException` during quick connection turnover. Source ownership checks fixed retired-server callback mutation, but the extended experience test exposed a remaining foreground-service start/stop race. Stops now queue a service command so foreground promotion is acknowledged before shutdown, with start IDs protecting newer requests. Regression coverage delivers retired callbacks after replacement and exercises 20 immediate foreground-service start/stop pairs, process survival and final service cleanup. The initial website check also caught an outdated v0.3.3 label assertion, which was updated and passed. Brand dependencies were installed in a local virtual environment after system Python rejected a global install.

Physical verification for this release: virtual-display testing **SKIP** because only the built-in display was online, with no independent display. No 22 → 23 interactive privacy-permission upgrade, physical Android/iPad streaming, Intel runtime or endurance test was performed in this release session. The iPad measurements below are inherited, separately scoped evidence.

Android high-refresh and iPad native-resolution high-refresh are experimental. A requested or negotiated frame rate is not evidence of physical display refresh. Two-device streaming, sustained high-refresh behavior, Intel runtime and long-duration reliability require separate hardware acceptance.

An isolated iPad capacity replay on a 13-inch M4 iPad Pro (2024), iPadOS 27.2, decoded 7,200 pre-encoded frames per codec at a 120fps target during a 60-second authenticated Wi-Fi developer-tunnel replay. Metal presentation measured 61.21 FPS for HEVC and 61.17 FPS for H.264. The fixture used a test-only admission-budget override and did not include desktop capture or live encoding; this is decoder/presentation evidence, not a general 120Hz performance claim. Details are in the [Apple video guide](../guides/apple-video.md).
