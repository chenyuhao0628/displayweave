# Mac 接收端键盘与鼠标

v0.3.0-preview.1 已包含。实施和证据记录于[功能台账](feature-completion.zh-CN.md)。

## 许可与范围

两台 Mac 必须通过 TLS 配对。发送端明确允许桌面键鼠输入并授予辅助功能权限；接收端明确启用回传。开关默认关闭，只采集当前获得焦点的接收画面窗口内事件。Control–Option–Escape 在本机禁用回传并释放已按下输入。焦点丢失、关闭窗口、切换角色、取消许可和断线均释放按键/鼠标。接收端本身不需要辅助功能或全局事件监控。

回传 macOS 物理按键码、修饰键变化、鼠标移动、左/右/中键、点击次数和滚动。文本组合在发送 Mac 上完成，使用发送端键盘布局及输入法。剪贴板、文件传输、全系统按键捕获及同时发送/接收不属于此功能。

## 协议与所有权

只在已认证 Mac 接收端的 `hello.inputCaps` 中声明 `mac-input-v1`。发送端仅在本机许可、辅助功能、认证对端与能力检查均通过后，使用 `inputConfig` 下发新的 UUID `inputSession`；拒绝时提供可恢复状态。保留 `pencil-v1` 协商和已有触摸/滚动消息兼容性。

每条 `desktopInput` 消息携带授权会话 UUID、严格递增且有界的序号、事件类型与已校验字段。拒绝旧授权 ID、非有限坐标、非法键码/修饰键、超限位移及非法字段组合。更换授权前先取消旧输入状态，旧版明文连接不接受桌面键鼠事件。

接收端在派发前预留有界发送票据（队列与在途合计 64 条，每条不超过 4 KiB）。溢出时断开所属连接，避免丢失释放消息而造成卡键。票据和授权 ID 隔离新会话与旧回调。发送端最多跟踪 16 个按键及三个鼠标键，在产生 CoreGraphics 事件前检查序号和边界，并确定性释放状态。

指针坐标按视频等比适配区域映射，排除黑边。拖拽在画面外释放时仍以钳制后的坐标结束按键。目标为该会话捕获/创建的显示器，改变几何信息前先释放输入。AppKit 本地事件监控仅作用于画面窗口及其响应者，并随 View 清理。

## 验收

- 严格消息解析、能力/许可/加密门禁、序号/授权拒绝及非法数字/键码。
- 等比适配坐标、黑边、显示边界和画面外释放。
- 使用捕获事件的测试出口检查按键重复、多鼠标键、按键上限和幂等取消，不向用户桌面注入事件。
- 真实加密接收网络检查授权/配置/重置、过期/溢出隔离和断线；Mac 通用架构构建。
- 两台实机检查：布局/输入法、焦点切换、快捷键、拖拽/滚动、权限变化和紧急退出。自动化检查不能证明实际应用行为或时延。

## 启用和停止

发送端打开“设置 → 权限与诊断”，开启**允许接收端 Mac 的键鼠回传**并授予辅助功能权限。接收端在“键盘与鼠标”开启**从此 Mac 操作发送端**，然后聚焦接收画面。接收端开关仅在当前应用内生效，重启应用默认关闭；发送端许可会保存。状态会提示缺少配对、发送许可、权限或显示器准备。接收窗口内按 Control–Option–Escape 关闭回传。每次输入均检查发送端许可/权限；空闲期间变化最多两秒内检查。系统撤销权限可能阻止合成释放事件送达，但本机持有状态仍会清空。

## 自动化证据

50 组 Swift 自检通过，包含严格协议/几何测试和捕获 CoreGraphics 事件的测试，覆盖重复按键、拖拽、修饰键组合、边界、畸形消息、过期授权、16 键上限、目标更换和幂等取消。真实双向 TLS 下，生产 Mac 接收器通过默认关闭、键鼠回传、释放顺序、授权更换、撤销、队列饱和与旧票据隔离检查。Mac 通用架构 Debug 和 iOS Simulator 构建通过。没有向用户桌面注入输入。窗口按键路由及双设备应用行为仍列于实机验收矩阵；本轮未启动已安装应用。
