# 可靠性与使用体验升级

源码改进于 2026-10-26 完成，并包含在 [v0.3.1](release-notes-v0.3.1.zh-CN.md) 中。基线：`01613ef`；[审计](code-and-experience-audit-2026-10-26.zh-CN.md) 是历史证据，不代表更新后的源码状态或已发布版本。

## 范围与验收

1. **会话恢复（A01–A04）：** 随代际退役关键帧所有权；采集中断后应用接收端配置变化；限制编码失败恢复次数；旋转时保留真实相邻显示器关系。验证替换/迟到回调交错、永久错误和多屏几何，不创建虚拟显示器。
2. **视频策略（A05、A06、A10、T02、T03）：** 区分编码压力与网络拥塞，在健康活跃队列下恢复码率，短暂解码背压时保留预测帧引用，读取新旧遥测字段。验证生产策略和协议契约。
3. **接收端体验（A07、A08、B01–B04、T07、T10、T13）：** Android 视频/光标/输入保持比例一致；默认简洁状态；限制光标解码和首帧等待；按帧龄恢复解码；静止按住手势与无障碍控件。通过隔离 Android/iOS 运行夹具与合成视频验证。
4. **设置与性能（A09、T01、T04–T06、T08–T12）：** 如实展示请求值/生效值，提供明确 30 fps，解释分辨率/刷新率取舍，连接反馈包含操作建议。保留协议/资源边界，记录参数评估及尚需实机的实验。
5. **完成条件：** 每次提交执行相关回归，两端 Apple 构建、Android 测试/构建/lint、网页/文档/发布静态检查、安全/生命周期运行夹具、自查及可复现本地产物。分别记录实现、自动验证、UI 与实机证据。

兼容性：保留偏好键、项目/包/Bundle ID、帧格式、服务发现、配对、签名/更新身份及署名。发送/接收角色仍互斥。发行打包与在线验证单独记录在 v0.3.1 发布说明中。历史快照探针固定于基线；新回归必须验证修复后的生产行为。

## 实现与验证台账

第一轮实现 A01–A04：关键帧请求以不可变令牌持有并随所有者退役；记录采集实际应用的 hello；限制编码重试/重建；排列位置检查垂直轴重合（同时修复以前保存的错误方向）。永久错误最多重建两次，暂时忙/无输出每轮最多重试三次，连续五秒健康输出才恢复预算。

已验证：关键帧替换/重复回调，永久/暂时编码错误耗尽预算；几何回归基线失败、修复后通过；提取当前恢复方法的夹具在 `01613ef` 上失败，修复后配置变化/未变/锁屏用例通过。arm64/x86_64 通用未签名 Mac Debug 构建通过。不宣称实机采集/恢复已经验证。

第二轮实现 A05、A06、A10、B03、T02、T03。Mac 丢帧仅作诊断，网络决策需要发送/接收端证据；少量健康活跃排队也可恢复码率。低于原始目标时，Auto 连续健康 3 秒后提高 20%（接收端采样周期可能延长）；达到原始目标后仍以 5 秒/7% 探测。Mac 本地恢复不超过原始目标。Apple 共用两帧/50 ms 背压策略。iOS 兼容新旧 ping 字段，并为没有视频的连接设独立 15 秒期限；首帧之后的静态桌面不受此限制。

已验证：61 组 Swift 套件、真实回环接收背压/重连、当前 iOS 接纳方法夹具、遥测序列化和两端 Apple 构建。合成策略测试中 8→40 Mbps 在 38 秒内恢复；这不是实测网络结果。

## 接收端与设置完成记录

第三轮修复 A07/A08，并实现 B01/B04、T07/T10/T13：Android 视频、光标和触控共用保持比例的 Surface；新安装默认简洁状态，切换详情会立即替换现有文字，设置页提供可选择复制的完整诊断。光标压缩数据最多 512 KiB、解码尺寸最多 512×512，分配前检查有限归一几何值。手势持有的 120 ms 定时器支持静止按住，并在滚动、暂停、尺寸或会话变化时取消；移动阈值按两个轴各自的像素衡量。两级各 12 帧 FIFO 共用 150 ms 接收到提交解码器的期限，保留帧副本不重置计时，过期后清理依赖帧并请求关键帧。尊重系统旋转，触控释放调用自定义 Surface 的无障碍点击钩子，光标绘制复用矩形。

已验证：七组 Java 测试、Debug APK 构建与 lint（0 错误／21 警告，原为 25）。ClickableViewAccessibility 和 DrawAllocation 已清除；剩余警告涉及工具链更新、冗余 API 判断、资源／图标位置、国际化及有意使用的固定证书信任管理器，不声称全部解决。隔离 Android Keystore／TLS／撤销／后台检查通过。实际合成 640×360 视频中的方块现在约为 200×200，基线为 200×774。根据 UI 树进行的输入验证了黑边拒绝、中心坐标归一和松手前已到达的静止按下。这是模拟器证据，不是实体触控／延迟或完整 TalkBack 验收。

第四轮修复 A09、B02，并改善 T01/T06/T09/T13。设置在一次事务中把不可用手动预设归一到最近有效值；Auto 列出可能支持的请求值，每个会话解释实际编码／传输限幅。设备卡片显示编码尺寸、格式、目标 FPS 和实际吞吐。Apple 接收端增加分辨率／帧率优先和显式 30 fps 上限，多个解码能力范围也按所选优先级排序；新增回归在修复前失败、修复后通过。Android／旧移动端镜像保持比例并适配声明的解码尺寸。iOS 连接设置固定于底部安全区之上，正文保留无障碍字号，仅品牌内容限制字号上限。

已验证：设置持久化／归一和旧偏好键、30 fps、4K 细节与 120 fps 尺寸取舍、多能力范围、横竖屏镜像边界、两个 Apple 构建，以及 iOS 浅色／深色／大字体截图。隔离 iOS TLS 测试确认只有心跳的连接在 11 秒仍连接、18 秒已断开；重连并收到有效画面后，静态桌面持续 16 秒仍连接。既有 Pencil V2／V1／禁止动作隔离、呈现所有权、撤销和后台测试继续通过。

## 参数决策

| ID | 决策与依据 |
| --- | --- |
| T01 | 增加分辨率／帧率优先；保留声明的 4096×2304×60 吞吐范围和 H.264 安全回退。缩小编码尺寸可开放高刷新，不虚构解码能力。 |
| T02 | 允许健康活跃队列恢复，依据发送龄、完成延迟和 ≥95% 收发比例，非零占用不单独视为故障。 |
| T03 | 初始目标以下每健康 3 秒恢复 20%，以上保留每 5 秒 7%，默认冷却 3 秒。合成 8→40 Mbps ≤38 秒；实体振荡／清晰度待测。 |
| T04 | 保留 H.264 100 Mbps、HEVC LAN 100／USB 160、Benchmark 200 上限，并解释实际限幅；没有新增真机证据支持进一步提高。 |
| T05 | 保留平均值与一秒峰值关系。没有新增实体 IDR／清晰度／吞吐证据支持改变突发余量，先测量再决定数值。 |
| T06 | 显示最终编码像素并解释叠加缩放，保留 High／Native 默认值；镜像适配接收端尺寸。 |
| T07 | Android 两级 FIFO 共用 150 ms 接收到解码提交期限，保留参考链恢复和容量 12；不代表网络或端到端上限。 |
| T08 | 保留编码／发送／SCK 预算。扩大队列不自动证明呈现更平滑，须实体采集／延迟 A/B。 |
| T09 | 开放 30 fps，覆盖偏好往返和旧值兼容；提供明确的较低负载选择，不声称节电百分比。 |
| T10 | Android 静止 120 ms 后按下，移动可更早开始，第二指取消并转滚动；与 iOS 既有手势区分意图一致，保留输入边界。 |
| T11 | 保留协议期限与有限重连节奏，沿用实际阶段／状态和已有重试／取消操作；新增 iOS 首帧恢复，避免心跳掩盖无画面。 |
| T12 | 保留输入／帧格式／缓冲池限制；无证据支持无限工作，未来合并移动事件也必须保留释放／取消。 |
| T13 | Android 新用户详细指标默认关闭，即时简洁渲染、可复制诊断；iOS 大字体设置可达，保留老用户显式指标偏好。 |

- 61 组 Swift 套件和当前生产方法的捕获／接纳夹具通过。捕获夹具的非 Sendable 系统桩警告仍在，属于测试夹具限制，不是应用构建失败。
- 通用 arm64/x86_64 Mac Debug 与 iOS Simulator 构建通过。Mac Debug 还使用原有固定 Apple 身份签名，并通过仓库签名／身份校验；不代表公证或公开发布。
- 七组 Android Java 测试、Debug APK 和 lint 通过。普通 Gradle 单元测试任务仍为 NO-SOURCE，不计作额外测试。
- 真实 Apple↔Java 双向 TLS、Mac／iOS 钥匙串、安全 iOS 与扩展 Android runtime 均在一次性命名空间／模拟器／AVD 中通过，不改动生产应用或传输身份。
- 最终门禁通过：网页 TypeScript／client／SSR／预渲染及生成页面检查、98 对双语文档、发布链接（v0.3.0／8 个资源）、12 项 Apple 分发、20 项 Mac 签名策略与 36 项品牌资源。
- 已观察：Android 合成比例／指标截图与实际输入，iOS 等待／引导／设置的浅色／深色及最大无障碍字号；不声称 Mac 窗口或完整读屏验收通过。

复现命令见[开发指南](development.zh-CN.md)，包括 `tools/test-android-experience.py` 和顺序执行的移动端 runtime。日志／截图位于本地忽略目录 `build/diagnostics/upgrade-2026-10-26/`，最终开发产物位于 `build/deliverables/reliability-experience/`。产物 README 记录确切源码版本、哈希、签名／安装边界与本地用法。这些开发产物与 v0.3.1 正式 Release 包分别记录；发行与更新源验证见[发布说明](release-notes-v0.3.1.zh-CN.md)。

## 实机验收

待验证：真实 Mac 采集/虚拟屏恢复与旋转，双设备 LAN/USB 延迟与耐久，高刷新率解码能力，Intel 运行，耗电，VoiceOver/TalkBack 与真实触控/Pencil。交互虚拟屏测试前必须确认独立在线显示器，禁止通过重启 WindowServer 或远程访问清理测试。


实机验收步骤：

| 范围 | 执行与判定 |
| --- | --- |
| 采集／生命周期 | 独立显示器在线后，测试镜像和扩展、旋转、睡眠／锁屏／恢复，以及改变分辨率后重连；确认应用当前配置、恢复有界、屏幕位置稳定、角色／会话替换前已清理。 |
| 性能 | Apple silicon 和 Intel 发送端搭配不同档位 iOS／Android，在支持的 LAN／USB 上比较 1080p／1440p／4K、30／60／90／120 目标；记录编码／呈现 FPS、帧龄 p50/p95/p99、队列峰值、码率、丢帧、CPU／温度与文字／运动观感，每次只改一个参数。 |
| 耐久／输入 | 执行 30 分钟和 2 小时会话，包含受控拥塞、旋转／拔插及触控／Pencil／键鼠；检查资源残留、卡住的按键、恢复循环与振荡，不用模拟器时间代替缺失实测。 |
| 无障碍 | 检查 Mac 最小／默认窗口、键盘焦点和 VoiceOver；实体移动端检查双方向、最大字号、TalkBack／VoiceOver、设置可达、拖动／滚动取消及黑边拒绝触控。 |
