# 自动匹配桌面

日期：2026-10-27。本文描述尚未发布的源码改动，不代表已发布的 v0.3.2 下载。使用方式和限制参见[桌面分辨率指南](../guides/desktop-resolution.zh-CN.md)。

## 实现

自动匹配根据可用的发送端参考显示器、Mac 接收端宽高比，以及两端可用且合理的系统报告物理尺寸估算逻辑桌面。尺寸缺失或不合理时回退到比例匹配。移动接收端和没有安装身份的旧接收端保留接收端几何。需要更多细节时，1× Mac 接收屏可使用 2× 虚拟 backing；视频协商和回退仍受现有编解码能力范围约束。

[Apple 文档](https://developer.apple.com/documentation/coregraphics/cgdisplayscreensize(_:))指出，显示器 EDID 不可用时，`CGDisplayScreenSize` 可能按 72 dpi 估算尺寸。匹配策略会排除接近此回退值的数据，但看似合理的报告值仍不等于实体量尺。

检测到旧偏好时保留已有设备档位和旧版默认的接收端匹配。新安装默认自动匹配，并先记录默认值，避免后续连接偏好使其被误判为旧安装。没有任何持久偏好的旧安装无法与新安装区分。自动发送端监听屏幕变化，采用防抖与冷却，只在桌面计算结果变化时重配置；没有参考屏时保留现有桌面。回调会核对当前会话、显示器和接收端配置。

## 自动验证

`DesktopResolutionSelfTest` 覆盖客户的 2048×1152 点案例、竖屏和 1×/2× 选择、物理尺寸校验及缺失/异常字段、几何边界、接收端视频上限、按设备保存和旧偏好迁移。`DesktopMatchMonitorSelfTest` 覆盖事件合并、冷却、繁忙重建后的重新检查和停止清理；`DesktopMatchDisplaysSelfTest` 只读查询当前显示器，无可用屏时报告 SKIP。`MacReceiverNetworkSelfTest` 通过回环 hello 验证可选物理尺寸字段。`tools/test-desktop-match-update.py` 使用桩替代显示器操作，执行当前生产更新与重配置调度方法，覆盖参考屏缺失、几何不变、会话隔离、停止、显示器被替换、过期接收端信息和重建后的再次检查。

本机源码检查包括 Swift 独立测试门禁、通用架构未签名 Mac Debug 构建、文档检查及空白检查；还使用正常签名的开发版 Run 操作验证启动，未替换已安装正式版。

## 本机观察

在 macOS 26.5.2 的 Apple M5 Mac 上，内建显示器在线，只读参考屏查询成功。隔离的 AppKit 接收端夹具使用合成视频窗口完成打开/关闭、进入/退出全屏和模拟睡眠/唤醒。800×600 点的 1× 与 2× 虚拟屏各完成三轮创建、模式与释放检查。

另一次虚拟屏检查使用客户案例式的合成参考屏 2048×1152 点和接收端 2560×1440 点、2×。策略选择 2048×1152 点、2×，本机系统选定 4096×2304 backing 模式，临时虚拟屏随后释放。该检查未采集桌面，也未进行双设备视频传输。

已目视检查签名开发版在无接收端连接时的发送端首页。另用隔离预览渲染实际 `SessionRow`，以模拟连接数据、5K 桌面、视频尺寸警告和较长设备名检查 480×440 点窗口的浅色及深色外观，未观察到文字重叠。该预览未验证真实连接、实时更新或键盘导航。

## 待完成的实机验收

- 在客户发送端、普通显示器和 Mac 接收端记录设备型号、系统与应用版本、屏幕实体尺寸、当前逻辑模式、接收端全屏/内容区域、桌面 backing、编码尺寸、编码格式、目标与实际呈现 FPS；分别在发送端 2048×1152 和 2560×1440 设置下比较同一个窗口。
- 检查不同实体尺寸、竖屏、1× 接收屏、窗口模式及黑边，实际测量窗口和光标大小；覆盖重连、接收端旋转、发送端模式变化、热插拔、参考屏暂时消失及两台接收端同时工作，确认无过期回调和反复重建。
- 原生 5K 视频仍待实现。现有 Apple 范围为 4096×2304；5120×2880 桌面仍可能只传输 4096×2304，画面可能发软。后续扩大范围需要分别验证编解码能力、有界回退和真实 Intel/Apple 硬件性能。本机模式测试不能证明 5K 清晰度、吞吐或持续稳定性。
