# Feature completion plan and evidence

Baseline: `89d7d20`, 2026-10-16. This is the active source-development ledger. Installed and published p8 (build 15) is unchanged by this work. Physical acceptance is a separate gate. Historical audits retain their dated evidence; this ledger supersedes their pending-feature lists.

## Execution and completion

Order: F01 → F02 → F04 → F08 → F06 → F03 → F05 → F07 → F09 → F10/F11 → F12. Each round includes the relevant regression, build, paired guide update and a coherent commit. Security research may refine the implementation order; record concrete tradeoffs here. No concurrent agents are required.

Feature completion means implemented behavior and passing automated acceptance, not just a policy stub or design. A blocked external identity/artwork requirement remains visibly blocked while the supported tooling is delivered. No public release or installation replacement is implied. Before integrating, run all Swift suites, Android tests/build, both Apple builds, website production build, bilingual/release checks and whitespace checks. Preserve unrelated changes and synchronize only with `displayweave`.

### F01 — implemented in source

Migrated Mac feed including persisted-feed override; Android bounded availability fallback with TLS/metadata fail-closed behavior. Signing identities are unchanged. Regression first failed against the old configuration, then passed. Mac universal Debug build, Android six groups (including new UpdateClient transport tests) and assembleDebug passed. Live canonical feeds returned 200 and matched tracked p8 bytes. Old p8 still needs manual migration if Pages stays unavailable.

### F02 — implemented in source

Per-installation Native/1080p/1440p/4K selection now rebuilds only the affected extension session. Logical geometry is separate from decoder/quality scaling; mirror ignores the desktop override. Added failing-then-passing geometry, persistence, limit and mirror tests. All 38 Swift suites and Mac universal Debug build passed. See [usage and physical acceptance](desktop-resolution.md).

### F04 — implemented in source

Shared bounded H.264/HEVC parser, iOS explicit Apple envelopes, hardware-gated HEVC, one-shot timed H.264 fallback, and Apple refresh negotiation up to 120fps. iOS requests ProMotion cadence only while its video view is connected. 39 Swift suites, updated Mac network/bitstream tests, Mac universal Debug and iOS Simulator builds passed. iPad simulator exercised valid H.264, configuration rejection, unsupported HEVC fallback and no re-upgrade on the same connection; hardware HEVC presentation was unavailable there. See [scope and physical acceptance](apple-video.md).

### F08 — implemented in source

Mac benchmarks now sample process CPU over monotonic intervals (100% = one core; reset/invalid intervals unavailable). Android transport, executor tasks, server queues and asynchronous decoder input now hold explicit pooled leases with bounded storage/waits and cancellation/rejection cleanup. Metrics distinguish actual array allocation from idle-pool reuse; historical p8 counters are not directly comparable. Tests cover malformed/truncated frames, stale/replacement connection ownership, saturation, shutdown, exceptions, concurrent holders and binary/legacy bucket tails. 1,000 synthetic frames used one allocation / 999 reuses. All 40 Swift suites, Mac universal Debug, Android six groups and Debug assembly passed. Physical allocation/GC/latency A/B remains pending; see [the allocation contract](android-binary-frame-header-v2.md) and [benchmark units](benchmark-guide.md).

### F06 — implemented in source

Default-off Mac LAN handover is active only in Auto mode and after a matching Mac hello. Stable wired arrival uses an owned stop-before-start replacement; failures use bounded same-ID, interface-pinned recovery with Wi-Fi fallback. Candidate debounce, cooldown, per-minute transition cap, bounded identities/tasks, manual cancellation, explicit receiver-exit handling and role/settings generation checks prevent duplicate or resurrected sessions. Added failing-then-passing policy/runner tests, including cleanup ordering and stale waits. All 41 Swift suites, Mac universal Debug and bilingual checks passed. UI compilation was verified; the installed app was not replaced or launched for this round. Two-Mac route/interrupt acceptance remains pending; see [usage and limits](mac-lan-handover.md).

### F03 — implemented in source

Selected platform mutual TLS with a full certificate pin and a 256-bit out-of-band one-use invitation; [design and compatibility boundaries](secure-transport-design.md). Apple Security identities, Java/Android certificate construction, strict pre-application message codecs, shared golden vectors, atomic trust/revocation policy and app-scoped Keychain/Keystore persistence adapters are implemented. A one-year certificate is required by the exercised Apple SSL policy; Android uses its Keystore key to sign a leaf with explicit TLS usages. Apple↔Apple and both Apple↔Java directions passed real TLS loopback, including wrong server/client pins. Pairing tests cover expiration, one-use tokens, persistence failure, alias rejection, revocation/downgrade history and 128-record bounds. All 44 Swift suites, Mac universal Debug, iOS Simulator build, Android six groups and Debug assembly passed.

Apple admission and the usbmux loopback relay are now implemented as separately tested components. Admission enforces two pending sockets, a ten-second deadline, exact bounded reads, matching ready IDs and trust-revision checks against concurrent revocation. Real TLS tests cover pairing/reconnect, bad tokens, revoked peers, wrong ready ID, fragmented invalid/oversized frames and stalled sockets. The relay binds only loopback, accepts one client, forwards at most one 64 KiB chunk per direction and tears down its tunnel idempotently. All 46 Swift suites, Mac universal Debug and iOS Simulator builds passed.

Apple session integration now defaults to TLS on both receiver platforms and freezes sender pins across LAN, ADB and usbmux relay dials. Application output waits for authenticated matching hello, including reconnects. UI supports invitation generation/import, trusted-peer revocation, explicit legacy compatibility and identity rotation. Role/background/stop and security changes cancel owned admission and transports. Runtime testing found `-34018` with the ad-hoc Mac/data-protection combination; macOS now explicitly uses its login Keychain, while iOS retains data-protection storage. Both platforms passed actual identity/trust persistence, rotation, tombstone and stale-reference checks in isolated test scopes. A disposable iOS app uses Xcode-generated simulator signing, not hand-invented production entitlements.

All 48 Swift suites, Mac universal Debug and iOS Simulator builds passed after integration. The iOS pairing settings were inspected in light/dark modes in an isolated test app. Simulator tests observe the production scene policy from a view. The Keychain fixture now completes a normal UIApplication launch and reports through an app-container result file; the final Mac/iOS run also passed missing-key refusal and explicit repair. The production iOS receiver passed authenticated H.264, rejected-candidate isolation, live revocation and background listener shutdown. Fixtures and signing context are separate from production artifacts.

Android now defaults to pinned mutual TLS and advertises `security=tls-v1`; pairing, revocation, explicit legacy mode, identity reload/reset and background shutdown are integrated into the production UI/server. Pending admission has two workers and an absolute ten-second deadline, including trickled input. The same buffered streams continue into pooled application framing. Reader ownership is established before adoption; raw sockets close immediately and TLS wrapper cleanup drains on bounded background readers, including shutdown.

Real Android 35 emulator testing found two platform-specific faults that software-key JVM tests could not expose: Keystore TLS signing requires `DIGEST_NONE`, and Conscrypt TLS close performs network work that must not run on the UI thread. Both were reproduced before correction. The isolated fixture now uses the actual Keystore private key, checks persistence across process restart, missing-key refusal/repair and stale-state invalidation, then uses the real MainActivity pairing/revocation/legacy settings with an Apple TLS client through ADB forwarding. Light/dark UI, explicit plaintext enable/disable and background listener shutdown were inspected/tested. No production APK contains the test activity or invitation extraction code.

Combined evidence: 48 Swift suites; real Apple↔Java TLS in both directions; Android six groups, Debug assembly and Lint (zero errors); real Android Keystore/TLS/UI suite. TLS tests include ciphertext modification, malformed frames, absolute deadlines, preserved coalesced application bytes, active-session isolation and revocation. Lint also caught and corrected an API-33-only update metadata conversion and made the existing API-29 codec guard explicit. Apple builds/Keychain/receiver-video evidence is recorded above. Physical LAN/USB performance remains separate. No published or installed app was updated. See [source usage](secure-transport.md).

### F05 — implemented in source

Authenticated Mac keyboard/mouse forwarding now requires both local opt-ins and sender Accessibility. A fresh grant identifies each connection/target; bounded receiver tickets, strict wire validation and a 16-key/three-button injector prevent stale or accumulated input. Local AppKit monitoring is scoped to the focused receive view; focus loss, disable, close, role change, disconnect and permission/consent changes cancel held state. Control–Option–Escape disables forwarding. Existing mobile touch/Pencil remain separate; Mac cannot bypass this grant through legacy touch/scroll.

50 Swift suites, the updated production TLS receiver network suite (including saturation and replacement), Mac universal Debug and iOS Simulator builds passed. Captured event tests never post into the user's desktop. Window routing/shortcuts and two-Mac application/layout acceptance remain physical checks. See [usage and evidence](mac-receiver-input.md). No download or installed application was replaced.
