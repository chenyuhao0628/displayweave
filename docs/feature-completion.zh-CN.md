## 执行与完成定义

顺序：F01 → F02 → F04 → F08 → F06 → F03 → F05 → F07 → F09 → F10/F11 → F12。每轮执行相关回归和构建、更新双语指南并独立提交。安全方案核实可能调整顺序，须在本文记录实际取舍。不需要并行代理。

完成必须有真实实现与自动验收，不能只有策略占位或设计。外部证书/素材条件缺失时，交付可用工具并明确标记仍阻塞的外部部分。开发不隐含发行或覆盖安装。合入前运行全部 Swift 套件、Android 测试/构建、两个 Apple 构建、网站生产构建、双语/发布和空白检查。保留无关改动，仅同步 `displayweave`。

### F02 — 源码已实现

按安装身份保存原生/1080p/1440p/4K，仅重建受影响的扩展会话。逻辑几何与解码/画质缩放分离，镜像忽略桌面覆盖项。新增几何、持久化、上限、镜像测试先失败后通过；38 个 Swift 套件及 Mac universal Debug 通过。见[使用与实机验收](desktop-resolution.zh-CN.md)。

### F04 — 源码已实现

### F08 — 源码已实现

Mac Benchmark 已按单调时间区间采集进程 CPU（100% = 一个核心；重置/无效区间记为不可用）。Android Transport、执行器任务、服务端队列和异步解码输入已使用明确的池化引用，存储/等待有上限，并处理取消/拒绝后的释放。指标区分真正的数组分配与空闲桶复用，不能直接与历史 p8 计数对比。测试覆盖异常/截断帧、过期/替换连接的内存所有权、耗尽、停止、异常、并发持有及 Binary/Legacy 桶尾。1,000 个合成帧只分配 1 次、复用 999 次。40 组 Swift 自测、Mac 通用架构 Debug、Android 六组测试和 Debug 构建通过。实机分配/GC/延迟 A/B 尚待完成，详见[分配约定](android-binary-frame-header-v2.zh-CN.md)与[Benchmark 单位](benchmark-guide.zh-CN.md)。

### F03 — 源码已实现

已选定平台双向 TLS、完整证书指纹及通过可信外部渠道传递的 256 位一次性邀请，详见[设计和兼容边界](secure-transport-design.zh-CN.md)。已实现 Apple Security 身份、Java/Android 证书构造、严格的应用协议前置消息编码、共享标准向量、原子信任/撤销策略与应用独立 Keychain/Keystore 持久化适配器。根据实际 Apple SSL 策略采用一年证书；Android 使用 Keystore 私钥签署带显式 TLS 用途的证书。Apple↔Apple 和 Apple↔Java 双向真实 TLS 回环通过，包括错误服务端/客户端指纹拒绝。配对测试覆盖过期、一次性 token、持久化失败、身份别名拒绝、撤销/防降级历史和 128 条记录上限。44 组 Swift 自测、Mac 通用架构 Debug、iOS Simulator 构建、Android 六组测试和 Debug 构建通过。

Apple 认证准入和 usbmux 本机回环中继已作为独立组件实现并测试。准入限制为两个待认证连接、十秒总期限，精确有界读取，校验确认消息的身份，并使用信任修订号防止并发撤销被旧回调覆盖。真实 TLS 测试覆盖配对/重连、错误 token、已撤销对端、错误确认身份、分段无效/超长消息和停滞连接。中继仅绑定本机回环、只接收一个客户端，每个方向最多在途一块 64 KiB 数据，并幂等关闭所拥有的隧道。46 组 Swift 自测、Mac 通用架构 Debug 与 iOS Simulator 构建通过。

Apple 两种接收端已默认使用 TLS；发送端在局域网、ADB 和 usbmux 中继拨号期间固定身份与安全模式，包括重连在内，应用输出必须等待认证后身份匹配的 hello。UI 支持邀请生成/导入、设备撤销、显式旧版兼容及身份轮换。角色/后台/停止与安全设置变更取消所拥有的准入与传输。运行时测试发现 Mac 临时签名与数据保护钥匙串组合返回 `-34018`，因此 macOS 现明确使用登录钥匙串，iOS 保留数据保护存储。两平台均在隔离命名空间通过真实身份/信任持久化、轮换、防降级历史与过期对象禁用检查。一次性 iOS 测试应用使用 Xcode 生成的模拟器签名，不手写生产权限。

集成后 48 组 Swift 自测、Mac 通用架构 Debug 与 iOS Simulator 构建通过。在隔离测试应用中检查了 iOS 配对设置的浅色/深色界面。模拟器测试从 View 观察正式场景策略，钥匙串测试通过应用容器结果文件报告，避免短时进程输出丢失。测试环境与签名上下文独立于生产产物。

Apple 安全接入最终复测：Keychain 隔离应用使用正常 UIApplication 生命周期及容器结果文件；Mac/iOS 均通过密钥丢失拒绝、显式恢复、持久化、重置、撤销记录和旧引用失效测试。生产 iOS 接收代码通过认证 H.264、未授权候选隔离、在线撤销和后台监听关闭测试。

Android 已默认使用固定指纹的双向 TLS，并广播 `security=tls-v1`；配对、撤销、显式旧版兼容、身份重读/重置和后台关闭均接入正式 UI/Server。待认证连接由两个工作线程处理，并受十秒绝对期限约束，持续慢速发送也不能延长期限。认证后的同一缓冲流继续用于池化应用帧。接管前先保证读取任务拥有清理责任；原始 socket 立即关闭，TLS 包装对象由有界后台读取线程清理，停止时也会排空任务。

真实 Android 35 模拟器暴露了软件密钥 JVM 测试无法覆盖的两个问题：Keystore 的 TLS 签名需要 `DIGEST_NONE`，Conscrypt 关闭 TLS 会产生网络操作，不能放在 UI 主线程。均先复现后修复。隔离测试现使用真实 Keystore 私钥，验证跨进程持久化、密钥丢失拒绝/恢复和旧状态失效，然后用正式 MainActivity 的邀请/撤销/兼容设置，通过 ADB 转发与 Apple TLS 客户端连接。已检查/测试明暗界面、显式明文启用/禁用及后台关闭监听。正式 APK 不含测试 Activity 或邀请提取代码。

综合证据：48 组 Swift 自测、Apple↔Java 双向真实 TLS、Android 六组测试、Debug 构建及 Lint（零错误）、真实 Android Keystore/TLS/UI 测试。TLS 测试包含密文篡改、非法帧、绝对超时、保留合并到达的应用字节、活跃会话隔离和撤销。Lint 另发现并修复了仅 API 33 支持的更新元数据转换，并显式化已有 API 29 Codec 条件。Apple 构建/Keychain/视频证据见上文。实机局域网/USB 性能另行验收，未更新发布或安装的应用。详见[源码用法](secure-transport.zh-CN.md)。
