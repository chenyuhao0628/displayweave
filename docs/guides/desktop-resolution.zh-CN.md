# 每台设备的桌面分辨率

v0.3.2 在“发送 → 扩展”连接接收端后，可在对应连接行的“桌面大小”选择跟随接收屏幕、1920×1080、2560×1440、3840×2160 或 iMac 4K/4.5K/5K。竖屏自动交换宽高。选择按接收端安装身份保存，跨局域网/USB 与重启保留。没有身份的旧接收端使用原生；重装/重置接收端可能生成新身份。

修改后仅停止并重建该设备会话，先等待采集和传输资源清理，其他设备继续串流。重建期间禁用选择器。镜像捕获发送端实体显示器，不提供虚拟桌面分辨率选择。

这些值是**帧缓冲像素**，不是逻辑点。Retina 虚拟显示器使用 2× backing：3840×2160 像素对应 1920×1080 逻辑点，1920×1080 像素对应 960×540 点；非 Retina Mac 使用 1×。原生保留接收端逻辑尺寸和缩放。固定模式为 16:9（竖屏 9:16），不同比例接收端会留黑边。

画质仍独立把捕获/编码缩放为 50%、75% 或 100%。Mac 解码能力可能继续降低编码尺寸/FPS；未提供解码尺寸上限的移动接收端不超过其面板像素范围，但不缩小所选桌面布局。连接状态显示的是编码尺寸，可能与桌面像素选项不同。降低画质节省带宽，更改桌面像素则会重新排列桌面。

## v0.3.2 的 iMac 改进

新的“桌面大小”选择器增加 iMac 4K（4096×2304）、4.5K（4480×2520）和 5K（5120×2880），在 2× 下分别提供 2048×1152、2240×1260 和 2560×1440 逻辑点，已有保存档位的含义保持不变。“跟随接收屏幕”替代笼统的“原生”标签，展示接收端报告的逻辑尺寸，包含当前 macOS 缩放设置。设备卡片分别展示逻辑桌面/底层像素与协商的视频尺寸。

两台 5K iMac 使用相同 macOS 缩放时，先选“跟随接收屏幕”，接收端全屏。普通 3840×2160 档位仅有 1920×1080 逻辑点，铺满 5K 屏幕会放大窗口。接收窗口小于屏幕时，整个远端桌面始终会缩放到窗口内。这些桌面档位不会解除 Apple 视频的 4096×2304 解码范围。

设置默认开启“自动适配 Mac 编码负载”：持续测得编码压力时，分辨率优先保留视频细节并降低 FPS，帧率优先先降低视频尺寸，两者都不改变桌面几何。健康活动窗口可以逐步恢复初始运行参数。可关闭此功能；测试码率模式不启用。希望交互更流畅时选帧率优先，无需缩小桌面。参见[证据与验收](../verification/imac-resolution-performance.zh-CN.md)。

自动验证：几何/方向和非法边界、独立设置保存恢复、最多 128 台设备偏好、编码上限、镜像宽高比；现有会话生命周期测试覆盖替换前清理。Mac universal Debug、63 个 Swift 套件及捕获/负载/准入夹具通过。实机仍需验收：两台接收端同时工作，仅修改其中一台，检查窗口与光标映射、竖屏旋转、重连，并在独立显示器在线时确认虚拟显示器清理。
