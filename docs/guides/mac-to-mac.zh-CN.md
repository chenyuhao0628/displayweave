# Mac 与 Mac 局域网互联

v0.3.1 支持任一 Mac 发送或接收，每次单向扩展/镜像。两端均需 macOS 14+。双 Mac 实机性能与耐久仍待验收。

## 连接步骤

1. 两台 Mac 连接同一 Wi-Fi 或以太网局域网。访客网络或客户端隔离可能阻止发现。
2. 在接收 Mac 选择 **接收屏幕**，设置接收显示器。在“安全与配对”生成邀请，将其通过可信渠道交给发送 Mac。
3. 在发送 Mac 的“安全与配对”导入邀请。选择 **发送屏幕**、**Auto** 或 **局域网**，再选择匹配设备。邀请两分钟内有效；成功后保留配对。
4. 选择扩展或镜像。扩展可按设备选择[桌面像素](desktop-resolution.zh-CN.md)，再在系统显示器设置中排列；镜像保持源显示器几何。
5. 默认使用发送 Mac 的键鼠。需要在接收 Mac 操作时，按[键鼠指南](mac-receiver-input.zh-CN.md)启用双端许可。Control–Option–Escape 可在接收窗口停止回传。
6. 关闭画面窗口或点击 **断开连接** 结束会话但保留发现；**停止接收** 关闭监听。切换角色先清理旧资源，再启动新角色。

角色跨启动保存；关闭控制窗口不等于退出。睡眠停止接收，唤醒后恢复已启用的监听。一次接受一个发送端。设置通过齿轮或 Command-comma 打开。

## 权限与能力

接收需要允许本地网络及入站防火墙连接；不需要屏幕录制或辅助功能。发送需要屏幕录制；注入键鼠/Pencil 还需要辅助功能。请勿全局关闭防火墙。

默认使用固定证书指纹的双向 TLS。Bonjour 服务 `_opensidecar._tcp` 和 TCP 9000 保持兼容。旧版连接仅可显式启用未加密兼容并使用可信网络；认证失败不回退明文。详见[配对](secure-transport.zh-CN.md)。

硬件支持时协商 HEVC，并保留 H.264 回退；屏幕、编码包络和像素吞吐共同限制最高 120fps 目标，不能保证实际刷新率。解码尺寸上限为横屏 4096×2304 或竖屏 2304×4096；较大桌面按比例缩放编码。[Apple 视频指南](apple-video.zh-CN.md)解释能力和性能区别。

Thunderbolt Bridge 或 link-local 以太网可作为绑定接口的候选，[有线/Wi-Fi 切换](mac-lan-handover.zh-CN.md)默认关闭。普通 USB-C 线缆本身不创建网络。音频、双向同时视频与互联网穿透不在此功能内；扩展使用私有 `CGVirtualDisplay` API。

## 验证

完整[开发门禁](../development/workflow.zh-CN.md)已通过，见[本版证据](../releases/v0.3.1.zh-CN.md)。自动测试覆盖策略、真实 TLS、合成视频、输入授权和过期会话隔离；不会证明两机延迟或持续高刷。实机仍需双向、扩展/镜像、Wi-Fi/以太网、Retina、睡眠/唤醒、输入及 30 分钟/2 小时耐久。交互虚拟显示测试必须先确认独立在线显示器，否则 SKIP。

环境：Apple Silicon，macOS 26.5.2，Xcode 26.6。

| 检查 | 结果 |

| macOS Debug 构建 | 通过；同时构建并确认 arm64、x86_64 两种架构 |
| iOS Simulator 构建 | 通过 |
| Android `test assembleDebug` | 通过 |
| 网站构建、中英文配对、发布链接检查 | 通过 |
| 实际开发应用接收窗口 | 本机合成四色 H.264 画面成功显示 |
| AppKit 生命周期测试 | 打开/关闭窗口、进入/退出全屏、模拟睡眠/唤醒通知、监听清理通过 |
| 虚拟显示器实测 | 800×600 点的 1× 与 2× 模式尺寸及释放通过 |

角色协调测试在旧角色清理挂起期间验证新角色不会启动。网络测试使用随机回环
端口，验证单发送端、无效帧、重连及停止/重启隔离。以上不等同于两台实体 Mac
互联；Intel 仅完成编译，macOS 14/15 运行、真实睡眠唤醒、多显示器切换、
双机 Wi-Fi/以太网性能和长时间耐久仍待实机验收。

后续复跑时主机合盖，内置屏幕离线，仅余测试虚拟显示器；当时的释放检查未通过，
不能据此确认代码根因。交互测试现要求存在独立活动显示器，否则明确输出 SKIP。
上述 1×/2× 通过记录来自此前开盖运行，合盖/无物理显示器场景仍未验证。若测试中途
合盖后系统仍列出测试显示器，请先恢复物理显示器，再检查显示器列表；不要把此状态
计入已完成的释放验证。

## iMac 缩放与持续编码负载（源码更新）

v0.3.1 之后的源码增加 iMac 4K/4.5K/5K 桌面档位、接收端逻辑尺寸标签及基于实际编码负载的适配。使用“跟随接收屏幕”与接收端全屏对齐桌面大小；选择帧率优先可降低传输负载而不重新排列窗口。这些修改尚未发布。参见[桌面分辨率](desktop-resolution.zh-CN.md)和[iMac 验证证据](../verification/imac-resolution-performance.zh-CN.md)。
