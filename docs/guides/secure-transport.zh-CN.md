# 安全连接与配对

v0.3.1 的 Apple 与 Android 已包含此功能。请升级发送端和接收端，再按下文邀请流程配对。旧版应用需要显式不安全兼容选择，见[发布说明](../releases/v0.3.1.zh-CN.md)。

## 首次连接

1. 在接收的 Mac、iPhone、iPad 或 Android 打开**设置 → 安全与配对**，生成接收配对邀请。保持接收端在前台监听。
2. 通过可信渠道将 `DW1.` 邀请复制到发送 Mac，在其**安全与配对**设置导入，再返回设备列表。
3. 通过局域网或 USB 选择对应设备。邀请固定接收端证书，选错线缆/设备会验证失败。成功后两端保存信任，重连无需邀请。已配对的两台 Mac 可以交换发送/接收角色。

邀请两分钟后过期，只能授权一个新对端。五次错误 token 尝试关闭窗口。邀请只留在内存，不写入发现记录或持久化偏好。平台支持时剪贴板副本两分钟后过期；macOS 仅在剪贴板未改变时清除本次副本。不要公开邀请，关闭窗口会取消待认证连接。

## 管理信任

设置列出已信任/已撤销设备及完整证书指纹。**撤销**会关闭该设备会话并取消待认证连接。撤销保留历史，防止旧配对静默变成明文连接；重新配对必须使用新邀请。

传输证书有效期一年。过期或身份材料丢失时，显式**重置本机传输身份**，然后在另一端撤销旧配对，再重新配对。重置关闭会话、禁用旧内存信任对象，并保留已撤销设备记录。钥匙串错误时拒绝连接；解锁钥匙串后使用**重新读取安全状态**再重试。传输身份与应用签名、Sparkle、Android 更新和 ADB 授权互相独立。

macOS 使用登录钥匙串。v0.3.0-preview.3 同时固定 Apple 签名身份；两份不同的签名测试程序已验证同一钥匙串传输身份和配对记录延续。iOS 使用应用的数据保护钥匙串，保护级别为 `WhenUnlockedThisDeviceOnly`。身份存储出错时，私钥与信任记录不会回退到文件。重新签名的 iOS 应用必须保留签名生成的有效应用标识；改变签名/访问组身份可能导致旧钥匙串数据不可访问。

Android 私钥保存在不可导出的 Android Keystore 条目中，只有公开证书和有界设备记录存入应用私有偏好。云备份和设备迁移均排除此数据。**重新载入安全状态**会禁用旧内存对象；重置保留撤销历史，并可继续进程退出前已明确记录的重置操作。Android 在邀请使用、过期、取消或后台时清除自己复制的邀请，但不会覆盖用户后来改写的剪贴板。

## 旧版应用

接收端明文监听和发送端明文许可默认均关闭。连接旧版应用时，必须手动启用对应的**未加密旧版兼容**选项，并使用可信网络。改变模式会断开相关会话。新发送端拒绝任何有配对历史的旧版 hello 身份，包括已撤销记录。TLS/认证失败不会打开旧版模式或用明文重试。

端口仍为 `9000`，Bonjour 仍为 `_opensidecar._tcp`，TLS 内的应用帧格式不变。安全接收端在发现信息中增加 `security=tls-v1`。剥除该字段不能改变已配对发送端的证书固定值。ADB 转发和 usbmux 使用相同认证流；Mac 的 usbmux 中继只接受一个本机回环客户端，且只转发加密字节。

## 验证边界

自动化测试覆盖真实平台 TLS、配对、非法准入长度、超时、撤销、严格 hello 身份、有界中继转发，以及 Mac 接收端的合成 H.264 视频。这些测试不捕获用户桌面。源码 UI 单独编译，不覆盖用户已安装应用。两设备局域网/USB 性能与长时验收仍属于实机测试。详见[执行台账](../archive/plans/feature-completion.zh-CN.md)和[协议/安全设计](../reference/secure-transport-design.zh-CN.md)。
