# Mac 有线／Wi-Fi 切换

v0.3.1 已包含，默认关闭。两台 Mac 实机验收尚待完成。

## 使用

在设置 → 通用启用 **Mac 有线／无线自动切换**，连接方式选择 **自动**。默认关闭，与用于设备出现时连接空闲设备的 **自动连接直连 Mac** 独立。仅局域网和仅 USB 模式不会执行 Mac 自动切换；`-autostart NO` 禁用这两项自动行为。

先正常连接 Mac 接收端。hello 确认其安装 ID 与 Bonjour 广播一致后，持续存在至少两秒的直连候选可以替换当前局域网连接。先等待旧捕获、虚拟屏幕、启动过程和传输资源清理完成，再打开新连接。新 Bonjour 解析与 TCP 固定在选中的接口，会话行显示接口名。切换会中断画面，可能重建扩展桌面。

意外断连耗尽现有 10 秒宽限后，Auto 可通过广播相同 Mac 安装身份的其他接口恢复。失败直连接口在本次恢复序列中被排除，即使后来被发现为普通局域网；回退时优先 Wi-Fi，再考虑普通路由以太网。不使用其他身份或无身份候选。安装身份只用于路由匹配，不能代替 TLS 配对认证；显式旧版兼容需可信局域网。

## 限制和控制

- 恢复最多五轮，依次等待 0.5、1、2、4、8 秒；每次连接最多等待五秒接收匹配的 Mac hello。仅 TCP 连接成功不算就绪；没有候选也消耗一轮。
- 有线升级的冷却期为 15 秒。每个对端 60 秒内最多三次自动切换；频繁失败或恢复耗尽后停止自动操作，直到手动连接或重启应用。
- 策略最多记录 256 个身份，同时最多运行 32 个对端切换。Android USB 恢复保持独立行为。
- **取消恢复**、**全部断开**、手动断开、切换角色及连接方式均取消待执行操作。接收端主动退出不会启动切换；旧任务和旧会话回调无法启动替代会话或更改其状态。
- 取消或耗尽后，检查接收端、线缆/网桥或 Wi-Fi，然后点击 **连接**。原有空闲设备自动连接选项也尊重手动断开状态。

直连分类仍是链路本地有线启发式判断：无 DHCP 的交换机可能表现得像专用线缆。普通 USB-C 线不会自行建立网络，详见[直连设置](hevc-wired-pencil.zh-CN.md)。

## 验证和实机验收

策略及执行器测试覆盖同 ID 选择、稳定出现、冷却/抖动、有界状态/重试、手动退出、先停后启、取消和等待中的 generation 变化。Mac 通用架构 Debug 和完整 Swift 自测通过。这些测试没有捕获桌面、创建虚拟显示器或证明实机网络切换效果。

使用两台 Mac 双向测试：Wi-Fi → 网桥/以太网出现；保留 Wi-Fi 拔线；有线候选失败后 Wi-Fi 回退成功；Wi-Fi 不可用；快速拔插；接收端退出；清理/等待 hello 时取消；切换角色/连接方式；耗尽后手动重连。确认每个接收端只有一个发送流水线、无输入卡住、接口标签正确及旧虚拟屏幕移除。记录中断和重连时间、分辨率与编码，测量前不得宣称无缝或实机已验证。
