# 拟议 Android 接收端会话控制

这些源码修改尚未发布。

设置按钮四秒后降低透明度，但仍保留在右上角可访问树中；点按可恢复不透明度并打开设置，视频视口保持不变。光标每个 UI 动画帧只保留最新位置；TCP 顺序不变，延迟改善尚未确认。

两个 FPS 试验默认关闭。60/90 FPS 选项在 PerformancePoint 不覆盖时额外查询解码器尺寸/帧率范围（不超过 90 FPS）。原生 60 在尺寸受支持时绕过吞吐量声明，允许在 2400×1080（含竖屏）以内试用 60 FPS。Hello 和所选解码器报告使用相同策略。Mac 还需要 100% 画质。出现延迟或错误时关闭并重新连接；没有基于实测吞吐量的自动回退。

当存在活跃 Mac 连接时，connectedDevice 前台服务在 Activity 隐藏期间保持前台优先级；未连接时空闲退后台仍会停止监听。活跃会话期间 Surface 销毁会释放解码器但保留认证连接；返回后重新配置解码器并请求关键帧；若在后台断开则立即停止服务器与服务。

## 证据与缺口

一台 Redmi 10（Android 13 / MIUI、加密局域网）操作人员确认切换应用约十秒后返回仍保持连接并恢复画面。发送端显示原生 2400×1080 / 60 FPS 目标和 50% / 90 FPS 目标，但尚未证明持续呈现 FPS。光标改善未确认。

服务器仍由 Activity 持有。Activity/进程销毁会停止会话，服务不能恢复被杀死的会话。长时间后台、息屏/Doze、拒绝通知、厂商回收、Surface 竞争及解码错误尚未验证。这并非完整的服务托管后台接收端。
