# Mac 本地拥塞与恢复

本文描述 2026-10-26 源码迭代，不代表新的已发布版本。PR 8 引入本地下降通道，后续工作增加 Mac 接收端恢复。本轮实现与验证见[升级记录](reliability-experience-upgrade.zh-CN.md)。

## 采样与所有权

Auto 模式下，发送端每 200 ms 采样待发送数量／预算、最老发送龄、编码／发送 FPS 和完成延迟。每次发送持有自己的单调时间戳和标识；完成回调只移除自己的条目，旧连接晚到回调不能减少替换连接的计数。编码输出处理串行运行于发送端队列。

连续两个样本达到发送预算，或存在待发送且最老发送龄增长超过 1 ms 时，在编码／传输边界内降低目标 12%。本地与接收端下降共用一秒保持期和决策序号；接收端压力可单独降低 20%，但不能在保持期内立即重复本地下降。Manual 和 Benchmark 不自适应。

## 恢复

Mac 接收端不发送移动端的 `stats` 消息。本地恢复允许预算内的活跃队列：最老发送龄和完成延迟分别不超过 `max(8 ms, 一帧编码间隔)`，成功发送 FPS 至少为编码 FPS 的 95%。非零队列不再单独阻止恢复；超过一秒缺失采样会重置健康区间。

连续健康三秒后提高目标 20%，默认独立升码率冷却为三秒。没有接收端测量时，不会超过原 Auto 目标。移动端在初始目标以下也采用 20%／3 秒恢复，超过初始目标的探测保持 7%／5 秒；实际接收端采样间隔可能延长等待。

Mac 捕获跳帧和编码输出丢帧只用于诊断，不再单独表示网络拥塞；本地队列／发送龄压力和接收端特定信号仍然有效。见[自适应码率](adaptive-bitrate.zh-CN.md)。

## 验证与限制

生产控制器回归覆盖队列／发送龄确认、有界下降、共用保持期、迟到／非法采样、健康活跃队列恢复、Manual／Benchmark 稳定性和初始目标上限。合成接收端策略测试的 8→40 Mbps 恢复在 38 秒内完成。这是策略执行结果，不是实测网络表现。Benchmark 序列化保留决策来源／触发／序号、队列龄与完成延迟。

满队列仍可能来自调度压力，双样本确认不能消除所有误判。12% 下降、200 ms 采样和恢复阈值仍需实体 A/B。应在同一场景比较目标／实际码率、发送龄、帧龄 p50/p95/p99、呈现 FPS、清晰度和振荡；包含重连和传输切换以验证所有权。实体 LAN／USB 拥塞与耐久证据仍待补充。
