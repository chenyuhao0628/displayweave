# UI audit and acceptance — 2026-10-16

Scope: native Mac/iOS/Android UI, first-class OpenDisplay connection entry, and GitHub release v0.3.0-preview.2 (17). Design authority: [UI standard revision 2](ui-guidelines.md). Interoperability: [OpenDisplay guide](opendisplay-compatibility.md).

## Findings and implementation

| Finding | Implementation |
| --- | --- |
| Sender incorrectly said all LAN traffic was unencrypted | Main-screen security mode explains actual policy; active session labels retain negotiated encryption |
| Setup, diagnostics and live state competed for attention | Mac workspace uses shared sections; settings group connection/application controls; receiver pairing precedes display/input options |
| Failures were capped at two lines | Device/session names and error text wrap; retry and diagnostic actions remain visible |
| Old OpenDisplay entry was buried in security settings | Equal main-screen mode choices on all three platforms; sender may connect both new and old peers |
| Early OpenDisplay hello without install ID was rejected | Explicit anonymous legacy admission, tested before/after fix; known identity and TLS downgrade guards retained |
| Android occasionally stopped listening after a compatibility-mode change | Reproduced `EADDRINUSE` during replacement; six initial bind attempts with at most 250 ms total retry delay, canceled by stop; persistent conflicts still report recovery guidance |
| Mobile setup copy drifted and Android settings lacked headings | Shared Apple three-step guide, bounded mobile content, Android shared panel/heading/button styles and sections |
| Permissions relied on colored glyphs | Mac permission rows also say Allowed / Not allowed / Check required |

Presentation remains separate from transport/lifecycle ownership. Existing preference keys, bundle/package identities, Bonjour and wire framing are retained. No static tests mirror visual structure.

## Automated verification

Passed locally:

- `./tools/run-swift-self-tests.sh`: 52 suites, including an anonymous OpenDisplay admission test observed failing before the fix and passing after it, upstream-style Apple configuration and real H.264 loopback.
- Universal Mac Debug/Release, iOS Simulator and unsigned device Release builds; Android `test assembleDebug lintDebug` and signed Release (six plain-Java groups). The new Android accessibility heading is gated to API 28, preserving minimum API 26.
- Actual Apple↔Java TLS; Mac/iOS Keychain; iOS encrypted video/Pencil, presentation ownership, revocation and background stop; Android Keystore/TLS, UI pairing/revocation and main-screen legacy→secure listener restoration. The listener replacement regression failed before the fix and passed afterward, covering transient conflict recovery, permanent conflict bounds and stop cancellation. UI tests wait for bounded asynchronous listener replacement and retain bounded failure diagnostics.
- Website production build, bilingual docs, release references and `git diff --check`; 12 Apple distribution tests and 36 reproducible brand exports.
- DMG/ZIP consistency, universal Mac slices, unsigned iOS arm64, unchanged Android signing certificate and independent Ed25519 verification of the Mac update archive.

Full logs/screenshots remain under ignored `build/` paths; invitations and private identifiers are excluded from committed evidence. Hosted checks and publication are recorded in the release notes, not substituted with local success.

After reproducing Android's transient bind failure, eight consecutive main-screen encrypted → legacy → encrypted cycles and background shutdown passed in one disposable AVD with the fix.
